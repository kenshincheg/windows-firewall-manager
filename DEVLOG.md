# Журнал разработки — Windows Firewall Manager

## 2026-10-24 — Проверки жизненного цикла и исправления 0.4.2

На отсоединённых COM-объектах сначала воспроизведены два сбоя: создание Any/application-правила падало на SetLocalPorts, а неверный порт оставлял изменённые Enabled/Description. Затем исправлены вызовы портов для Any и последовательность смены протоколов, добавлены полная валидация до setters и предварительная проверка на отдельном объекте. Enabled устанавливается последним. Глобальная транзакция COM не заявляется.

Редактирование переведено с имени на исходный снимок выбранной копии. Поиск снимка общий для сохранения и удаления, без промежуточного вектора и преобразований BSTR в String для сравнения. Отклоняются устаревшие снимки и неоднозначное редактирование через публичный API по одному имени. Состояние формы хранит исходное правило, а не дублирующие имя и снимок. Удаление другой копии с тем же именем не сбрасывает черновик.

ICMP и другие протоколы представлены `Protocol::Other`, корректно отображаются и защищены от смены на Any ограниченной формой. Поддержаны wildcard/списки портов, проверка нулевых символов и прав в обработчике сохранения. Сообщение об успешном сохранении сохраняется после reload.

Пройдено 52 обычных теста и два live-сценария, повторённые после оптимизации поиска: матрица 24 добавления / 72 редактирования / 24 удаления плюс одинаковые имена, переименование, ошибки ввода, устаревшие снимки и адресное удаление. Все live-правила отключены; исходная политика после каждой группы сверена. Независимая проверка Windows: 589 → 589, различий нет, временных правил 0. Расширенные поля, профили, приложение и Enabled проверены также на отсоединённых COM-объектах.

Нативные клики и сетевые подключения не автоматизировались; тестировались методы кнопок. Резервные копии и отчёт: `backups/firewall-tests-2026-10-24-recheck/`. Первый прогон сохранён в `backups/firewall-tests-2026-10-24/`. Общая очистка реальных дублей в этом задании не запускалась.

## 2026-10-23 — Повторная проверка и исправления 0.3.2

При сравнении рефакторинга регрессий переноса функций не обнаружено. Проверка граничных состояний выявила существовавшие ранее дефекты:

- Скрытый фильтром выбор оставался доступен действиям. Теперь фильтр сбрасывает скрытый выбор, обработчики заново проверяют видимость и индекс, кнопки изменения/удаления отключаются без допустимого выбора. Удаление дополнительно проверяет права.
- Переименование удаляло исходное правило перед созданием нового. Теперь обновляется существующий INetFwRule и последним меняется Name, без Remove/Add. Сохраняются расширенные свойства. Запись свойств COM по-прежнему не является общей транзакцией: отдельные свойства применяются Windows немедленно.
- EnablePending / DisablePending позволяли повторные операции. Теперь действия заблокированы до перезагрузки с соответствующей подсказкой.
- Валидация имени не учитывала ограничения Windows: запрещены all (без учёта регистра) и символ |; в описании также запрещён |. Проверки текста выполняются до изменения COM-свойств.
- ComGuard не вызывал CoUninitialize для успешного повторного CoInitializeEx (S_FALSE). Исправлен баланс вызовов. На отдельном тестовом потоке воспроизведено сохранение COM-контекста после прежнего освобождения; после исправления контекст освобождается.

Новые тесты перед исправлением воспроизвели четыре сбоя. После исправлений: 33 теста, включая переименование и отказ записи на отдельных NetFwRule-объектах, не добавленных в системный список. Проверены сохранение дополнительных свойств и исходного имени при ошибке. Реальные правила Windows в тестах не добавлялись, не удалялись и не изменялись. Проверены rustfmt, cargo check --all-targets, Clippy и release-сборка. Clippy содержит прежние стилистические предупреждения; они не подавлялись глобально.

## 2026-10-13 — Старт проекта

### Решение: COM вместо netsh
Используем `INetFwPolicy2` / `INetFwRule` через crate `windows`.
Плюсы: типизированные HRESULT, без парсинга CLI, штатные порты/диапазоны (`"21"`, `"45512-65534"`).

### Решение: egui + wgpu/DX12 + WARP
На системах без драйверов GPU OpenGL часто отсутствует.
DX12 через wgpu может работать на WARP (software DirectX).
Старт: DX12 GPU → при неудаче повтор с выбором WARP/CPU-адаптера → MessageBox с понятной ошибкой.

### Этап 1 — каркас
- `cargo init`, зависимости (`eframe` 0.32 / `egui` / `windows` 0.61), `app.manifest` + `app.rc`, `build.rs`, журнал.

### Этап 2 — firewall COM
- `list_rules` / `add_rule` / `remove_rule`
- Порты и диапазоны через `SetLocalPorts`
- In/Out, Allow/Block, ApplicationName, Profiles

### Этап 3 — model + валидация
- Парсинг `21` и `45512-65534`, проверка from <= to, имя, путь к программе
- Unit-тесты в `model.rs`

### Этап 4 — UI + тема
- Форма добавления + таблица правил + фильтр
- Тёплые голубые оттенки (`#0B3A5C` / `#2E8BC0` / панели `#E8F4F8`)

### Этап 5 — рендер без GPU
- `WgpuSetupCreateNew` с `Backends::DX12`
- `native_adapter_selector`: hardware, затем WARP/CPU
- Двойной старт `force_warp=false` → `true`

### Этап 6 — release / README
- `cargo build --release` → `target/release/firewall_windows.exe`
- Манифест admin встраивается **только в release** (иначе `cargo test` падает с os error 740)
- Debug-сборку запускать «от имени администратора» вручную при необходимости

### 2026-10-13 — Фикс запуска + иконка
**Причина падения:** `egui-wgpu` тянет `wgpu` с `default-features = false` (только `wgsl`), без `dx12` → паника `No wgpu backend feature...` сразу при старте (в release без консоли казалось, что «не запускается»).
